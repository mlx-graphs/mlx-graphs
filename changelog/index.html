Changelog¶

Every release of mlx-graphs, newest first, with the notes of its GitHub release and, for some versions, hand-written notes from CHANGELOG.rst. The packages are on PyPI.

0.6.0¶

2026-11-24 · Full diff · PyPI

Large graphs¶

  • Datasets: Reddit, Reddit2, Flickr, Yelp, AmazonProducts and PPI, with PyG's files, edges, labels and splits (checked equal to PyG's, benchmarks/quality/dataset_parity.py). Single large graphs are stored as safetensors after processing. PPI is read from the GraphSAGE release, as DGL's server is down.
  • Temporal sampling: NeighborLoader and LinkNeighborLoader take PyG's time_attr, input_time / edge_label_time and temporal_strategy ("uniform" / "last"): only neighbors not later than their seed are sampled, with node- or edge-level timestamps, each seed getting its own subgraph (disjoint=True, also available without time). Implemented as a vectorized numpy sampler; "last" gives the same mini-batches as PyG with pyg-lib.
  • Feature and graph stores: FeatureStore / GraphStore (PyG's remote backend API) with in-memory and on-disk (MemmapFeatureStore, MemmapGraphStore) implementations. NeighborLoader((feature_store, graph_store), ...) gathers only the rows of the sampled nodes, so node features larger than the memory can be used for training.

Features¶

  • Temporal Graph Benchmark (TGB) datasets: TGBLinkPropPredDataset (tgbl-wiki, tgbl-review, tgbl-coin, tgbl-comment, tgbl-flight) with TGB's chronological splits and precomputed one-vs-many negative samples (TGBNegativeEdgeSampler), and TGBNodePropPredDataset (tgbn-trade, tgbn-genre, tgbn-reddit, tgbn-token) with its label stream. TGBEvaluator computes MRR / Hits@k and NDCG@10 as py-tgb. The events, splits, negative samples and labels of tgbl-wiki, tgbl-review, tgbn-trade and tgbn-genre were checked to be identical to py-tgb's. New examples tgn_tgbl.py and tgn_tgbn.py train TGN with the TGB protocol (compared with py-tgb's PyG examples in benchmarks/tgn_comparison).

New API¶

  • Hierarchical and dense pooling, checked against PyG (outputs, auxiliary losses and gradients) and by training on PROTEINS in both frameworks (benchmarks/quality/pooling_quality.py):

    • dense pooling dense_diff_pool, dense_mincut_pool and DMoNPooling, with the dense layers DenseGCNConv, DenseSAGEConv, DenseGINConv and DenseGraphConv;
    • sparse hierarchical pooling EdgePooling (with unpool), ASAPooling, MemPooling and PANPooling (with PANConv), and the GraphUNet model;
    • GCNConv(improved=True) (self-loops of weight 2).

Point clouds and meshes¶

  • Layers PointNetConv (alias PointConv), PointTransformerConv, PPFConv, XConv, SplineConv (B-spline basis in MLX, any degree up to 3), GMMConv and FeaStConv, checked against PyG with copied weights (outputs and gradients).
  • Sampling and clustering: fps (farthest point sampling, one Metal threadgroup per point cloud; the same points as PyG with random_start=False), voxel_grid, nearest, graclus (parallel matching), consecutive_cluster, and the cluster poolings avg_pool, max_pool, avg_pool_x and max_pool_x.
  • Transforms SamplePoints, FixedPoints, NormalizeScale, Center, LinearTransformation, RandomJitter, RandomRotate, RandomScale, FaceToEdge, Cartesian, Distance, Polar and PointPairFeatures.
  • Datasets ModelNet (ModelNet10 and ModelNet40) and ShapeNet (part segmentation, downloaded from a Hugging Face mirror since the original URL is offline).
  • GraphData gets its number of nodes from pos when it has no node features, and offsets mesh triangles face in batches, as PyG does.
  • benchmarks/quality/pointcloud_quality.py trains PointNet++ and DGCNN on ModelNet10 with mlx-graphs and PyG.

Added¶

  • Molecular and 3D models, checked against PyG with copied weights (outputs and gradients) and by training both on QM9 and ESOL (benchmarks/quality/molecular_quality.py): SchNet, DimeNet, DimeNetPlusPlus and AttentiveFP.
  • Molecular datasets matching PyG's: QM9, ZINC (subset and full) and MoleculeNet (ESOL, FreeSolv, Lipophilicity, BACE, BBBP, HIV, Tox21, ...).
  • from_smiles, to_smiles, from_rdmol and to_rdmol with PyG's x_map / e_map featurization (rdkit is an optional dependency).

0.2.0: PyG parity¶

2026-11-22 · GitHub release · Full diff · PyPI

Detailed notes (CHANGELOG.rst)

This release brings mlx-graphs close to PyTorch Geometric in features and API: about 235 new public classes and functions, samplers and loaders for mini-batch training, heterogeneous and temporal graphs, graph transformers, and 18 new datasets. Every addition was checked against PyG: layers with copied weights (outputs and gradients), samplers statistically, and models by training them in both frameworks on the same data (benchmarks/quality/).

Highlights

  • Samplers and loaders: LinkNeighborLoader, HGTLoader, ClusterData / ClusterLoader, the GraphSAINT samplers, ShaDowKHopSampler, RandomNodeLoader, ImbalancedSampler, DynamicBatchSampler, DataListLoader, DenseDataLoader; Dataloader gains drop_last, follow_batch, sampler, batch_sampler, transform and collate_fn.
  • Heterogeneous graphs: to_hetero and to_hetero_with_bases turn a homogeneous model into a heterogeneous one, as in PyG (without torch.fx: see the docstring for the supported model patterns); HANConv, HGTConv, RGATConv, FastRGCNConv; the OGBMAG dataset.
  • Temporal graphs: TemporalData, TemporalDataLoader, TGNMemory and its building blocks, LastNeighborLoader, JODIEDataset, and the new mlx_graphs.metrics package (link prediction ranking metrics, AUC, AP).
  • Graph transformers: GPSConv, SGFormer, Polynormer, MultiheadAttention, PerformerAttention, positional encodings (LapPEEncoder, RWSEEncoder, PositionalEncoding, TemporalEncoding), LRGBDataset and GNNBenchmarkDataset.
  • Aggregations: the mlx_graphs.nn.aggr module (sum, mean, max, min, mul, var, std, median, quantile, softmax, power mean, LSTM, GRU, set transformer, graph multiset transformer, sort, MLP, LCM, deep sets, equilibrium, degree scaler, ...). MessagePassing(aggr=...) accepts a name, a list of aggregations (concatenated or combined with aggr_kwargs={"mode": ...}) or an Aggregation module.
  • PyG names: GraphData has the x, edge_attr and y aliases, GraphDataBatch has batch and ptr, and the norm layers are also exported under their PyG names (GraphNorm, PairNorm, ...).

  • Documentation:

    • new tutorials, each compared with PyG on accuracy and runtime: mini-batch training on large graphs, link prediction, temporal graph networks, heterogeneous graphs with to_hetero, and graph transformers with GPS; node2vec is now a single tutorial;
    • new pages: "Creating message passing layers" (user guide) and "Validation against PyG"; an updated "Coming from PyTorch Geometric"; an overview figure at the top of every tutorial.

New API

  • mlx_graphs.nn:

    • Message passing layers:

      • AGNNConv, ARMAConv, CGConv, ClusterGCNConv, DirGNNConv, DynamicEdgeConv, ECConv, FAConv, FastRGCNConv, FiLMConv;
      • GCN2Conv, GENConv, GINEConv, GPSConv, GatedGraphConv, GeneralConv, HANConv, HGTConv, LEConv, LGConv, MFConv;
      • MixHopConv, NNConv, PNAConv, RGATConv, ResGatedGraphConv, SSGConv.

    • Models:

      • PNA, EdgeCNN, DeepGCNLayer, LINKX, LightGCN, LabelPropagation, CorrectAndSmooth, MaskLabel, RECT_L;
      • graph autoencoders: GAE, VGAE, ARGA, ARGVA, InnerProductDecoder;
      • DeepGraphInfomax;
      • knowledge graph embeddings: KGEModel, TransE, DistMult, ComplEx, RotatE, KGTripletLoader;
      • SGFormer, Polynormer, TGNMemory.

    • Norms: BatchNorm, InstanceNorm, LayerNorm, GraphNorm, PairNorm, DiffGroupNorm, MessageNorm, MeanSubtractionNorm, GraphSizeNorm, HeteroBatchNorm, HeteroLayerNorm.

    • Pooling and graph construction: TopKPooling, SAGPooling, global_sort_pool, knn, knn_graph, radius, radius_graph.

  • mlx_graphs.transforms: AddLaplacianEigenvectorPE, AddRemainingSelfLoops, FeaturePropagation, IndexToMask, KNNGraph, LineGraph, LocalDegreeProfile, MaskToIndex, NormalizeFeatures, RadiusGraph, RemoveDuplicatedEdges, RemoveTrainingClasses, SIGN, SVDFeatureReduction, TargetIndegree, ToDense, TwoHop, VirtualNode.

  • mlx_graphs.utils:

    • graph generators;
    • subgraph, mask and self-loop helpers;
    • negative sampling for batches;
    • get_ppr;
    • assortativity, normalized_cut;
    • scipy conversions;
    • the scatter reductions var, std, mul, median and quantile.

  • mlx_graphs.datasets:

    • citation and web graphs: CitationFull, CoraFull, WikiCS, WebKB, WikipediaNetwork, Actor, HeterophilousGraphDataset;
    • knowledge graphs: FB15k_237, WordNet18, WordNet18RR;
    • synthetic graphs: FakeDataset, FakeHeteroDataset;
    • JODIEDataset, LRGBDataset, GNNBenchmarkDataset, OGBMAG;
    • a torch-free reader for .pt files (load_torch_file), which uses a restricted unpickler.

  • Dataset, GraphData and HeteroGraphData gain PyG conveniences, among them num_classes (inferred as in PyG), shuffle, to_homogeneous and the feature counts.

Changes that can affect existing code

  • Self-loops now default to PyG's behaviour.

    • GCNConv defaults to add_self_loops=True (it was False).
    • GATConv and GATv2Conv gain add_self_loops=True and fill_value="mean".
    • To keep the previous results, pass add_self_loops=False.

  • GIN: the act and norm arguments now also apply to the MLP inside every GINConv, as in PyG. Before, that MLP always used ReLU and no normalization.

    • Models with the defaults (act="relu", norm=None) are unchanged.
    • With norm="batch" or "layer", the MLPs gain norm layers, so weights saved before this change will not load as-is.

  • GAT: dropout now also applies to the attention coefficients of every GATConv / GATv2Conv, as in PyG's GAT. Before, it only applied between layers. Models with dropout=0 are unchanged.

  • LayerNormalization:

    • mode="graph" (the default) was broken and now matches PyG's LayerNorm.
    • mode="node" now uses the layer's own weight and bias. Its unused layernorm.* parameters are gone, so older checkpoints do not load strictly.

  • Index dtypes are int32 throughout. This covers:

    • the n_id, e_id and edge_index returned by NeighborLoader;
    • GraphDataBatch.batch_indices, batch and ptr;
    • the follow_batch vectors.

    Indexing with them works as before. int64 is used only for graphs with more than 2^31 - 1 nodes or edges.

  • GraphDataBatch indexes like a Python list of graphs.

    • Slices are clipped instead of raising: batch[:101] on a smaller batch, or batch[3:2], which gives [].
    • Negative steps work.
    • batch[num_graphs] raises IndexError.
    • Index arrays, lists and boolean masks are accepted.

  • MessagePassing(aggr="softmax") is now the softmax aggregation (SoftmaxAggregation), as in PyG and as aggr=["softmax", ...] already was. Plain string aggregations given with aggr_kwargs now use them instead of ignoring them.

  • Max and min aggregations split the gradient equally among tied values, as PyG does (e.g. with duplicate edges). Before, every tied value got the full gradient. The backward pass of the fused max/min kernels is slower as a result; forward passes are unchanged.

  • Initialization: HeteroDictLinear now initializes like torch.nn.Linear, as in PyG, instead of Glorot.

Fixes to previously released code

  • SAGEConv with a max, min, std or list aggregation and more input than output features projected before aggregating (max(Wx) instead of W max(x)).
  • SAGEConv gains PyG's root_weight. Without it, DirGNNConv(SAGEConv) kept a root projection in both directions and trained 2-3 points below PyG.
  • TUDataset dropped edge labels.
  • IMDB keyed its labels by "movies" instead of the "movie" node type.
  • NeighborLoader with out-of-range seed nodes read past the sampler's buffers. It now raises IndexError.
  • Batching graphs whose first graph has no nodes broke the edge offsets.
  • Unbatching turned int32 edge_index into int64.
  • QM7b downloads failed: the old http URL returns 400. It now uses PyG's https URL.
  • Tar extraction is now protected against path traversal and symlink escapes.

Tips when porting PyG code

  • mlx.optimizers.Adam has no bias correction by default, unlike torch.optim.Adam. Use Adam(learning_rate=..., bias_correction=True) to train the same way.
  • Batches of graphs of varying sizes create arrays of many different shapes. To bound memory, cap MLX's buffer cache with mx.set_cache_limit(...).

Known limitations

  • to_hetero:

    • It does not detect operations that mix rows across node types inside the model's __call__ (e.g. x.mean(0), sorting). PyG traces these per node type.
    • Copies without a reset_parameters() method are re-initialized by shuffling their weights.

  • GPS, SGFormer, Polynormer and the LSTM, GRU, set transformer and sort aggregations read the batch layout on the host. They work with nn.value_and_grad but not with mx.compile, unless the precomputed layout= argument is given (GPS, SGFormer, Polynormer).

  • TGNMemory's memory is not saved by save_weights. Use memory_state() and load_memory_state().
  • MLX 0.32.4 crashes when a compiled activation is applied to an empty matmul result. CGConv, NNConv and EdgeConv are guarded against it. Most layers still fail on graphs with zero nodes.

Summary¶

This brings mlx-graphs close to PyTorch Geometric in features and API, as release 0.2.0. It adds about 235 public classes and functions, each checked against PyG. The full list is in CHANGELOG.rst, which the docs show as the Changelog page.

  • Mini-batch training:
    • LinkNeighborLoader, HGTLoader, ClusterData / ClusterLoader, the GraphSAINT samplers, ShaDowKHopSampler, RandomNodeLoader, ImbalancedSampler, DynamicBatchSampler, DataListLoader, DenseDataLoader.

    • 11 norms, plus TopK / SAG pooling;
    • autoencoders, DeepGraphInfomax, knowledge-graph embeddings, LINKX, LightGCN, CorrectAndSmooth, PNA, EdgeCNN, and more.

0.1.0¶

2026-11-21 · GitHub release · Full diff · PyPI

mlx-graphs 0.1.0: faster message passing, PyG-parity layers and models, PyG benchmarks¶

On an M5 Pro, mlx-graphs now trains GNNs 5.6× faster than PyTorch Geometric on MPS and 5.8× faster than on CPU, with the same accuracy (median of 35 training benchmarks on 12 datasets, up to 58×). Compared with 0.0.11 (current main), a single layer is 1.5–2.7× faster on large graphs.

Performance¶

  • Fused message passing: layers whose message is a weighted sum of neighbour features aggregate with one sparse × dense matmul on the GPU (mlx-cluster kernels) instead of gather-scatter, so the [num_edges, features] message array is never built. This includes GAT/GATv2 (one SpMM per head). format="auto" switches from COO to the faster CSR kernel when the conversion pays off; it can be turned off globally or per block of code.
  • Cached GCN normalization for GCN, SGConv, APPNP, TAGConv and ChebConv on a fixed graph.
  • Vectorized coalesce, to_undirected, batching/collate and scatter_softmax.

New features¶

  • Layers: TransformerConv, GraphConv, SGConv, APPNP, ChebConv, TAGConv, EdgeConv, RGCNConv.
  • Models: GCN, GraphSAGE, GIN, GAT (v1/v2), MLP, with dropout, batch/layer norm and Jumping Knowledge.
  • Pooling / readout: AttentionalAggregation, Set2Set, JumpingKnowledge.
  • Transforms: Compose, structure transforms (self-loops, undirected, isolated nodes, largest connected component, …), RandomNodeSplit, RandomLinkSplit, feature transforms (OneHotDegree, Constant, AddRandomWalkPE, GCNNorm).
  • Utilities: subgraph, k_hop_subgraph, negative sampling, dropout_edge / dropout_node, to_dense_batch, to_dense_adj, get_laplacian, homophily, from_pyg / to_pyg.
  • Datasets: Amazon (Computers, Photo) and Coauthor (CS, Physics).

Fixes¶

  • Layers are initialized as in PyG (Glorot for GCN/GAT, PyTorch's default Linear init for GraphSAGE/GraphConv). GraphSAGE no longer collapses on Amazon: 72% → 91% test accuracy on Photo, 63% → 78% on Computers.
  • GAT attention vectors use Glorot initialization.
  • Dataloader reshuffles on every pass and has a len() (number of batches).

Behaviour changes¶

Code written for 0.0.11 may behave differently:

  • Layers initialize as in PyG, so trained results can differ slightly.
  • coalesce sorts edges by (source, destination) and no longer swaps the rows of edge_index.
  • Dataloader reshuffles on every pass when shuffle=True.
  • Requires mlx>=0.32 and mlx_cluster>=0.1.2. Dependencies are now minimum versions instead of exact pins.

Benchmarks against PyG¶

benchmarks/pyg_comparison compares mlx-graphs with PyG on MPS and on CPU, using the same models, data and hyperparameters:

  • Tasks: single layers on graphs of up to 2M edges, full-batch node classification on 8 datasets (Cora to ogbn-arxiv), graph classification on 4 TU datasets.
  • Training quality: training loss at every epoch and test accuracy over 3 seeds, so the comparison shows the models learn the same, not only that they run faster.
  • Isolation: each configuration runs in its own process under a 16 GB memory cap.
  • Version tracking: results are stored per version (results/<chip>/<version>-<commit>/), and history.py compares versions (0.0.11 → 0.1.0 in history.md).

Docs and README¶

  • README: new header with badges, the headline result and figure, and an updated benchmark section with the loss and accuracy curves.
  • Docs:
    • new Benchmarks page (figures only, generated by plot.py);
    • new tutorial Coming from PyTorch Geometric;
    • Quickstart gains a models-and-training section;
    • the Graph Classification notebook is fixed and re-executed;
    • Amazon and Coauthor are on the Datasets page;
