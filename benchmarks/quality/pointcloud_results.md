# Point cloud classification: mlx-graphs vs PyG on ModelNet10

Generated by `pointcloud_quality.py` (see its docstring for the setup):
1024 points per shape sampled once, batch size 32, Adam lr 0.001. mlx-graphs on the GPU, PyG 2.8.1 on the CPU (`torch_cluster` for fps / radius / knn). Accuracy: test accuracy at the last epoch (and the best epoch). Time: mean training time per epoch (excluding the first epoch) and test evaluation time.

| model | epochs | seed | framework | test acc (last / best) | train s/epoch | test s | final train loss |
|---|---|---|---|---|---|---|---|
| dgcnn | 3 | 0 | mlx (mlx gpu) | 78.0 / 78.0 | 116.2 | 21.9 | 0.441 |
| dgcnn | 3 | 0 | pyg (torch cpu (8 threads)) | 80.2 / 80.2 | 121.9 | 16.2 | 0.434 |
| pointnet2 | 5 | 0 | mlx (mlx gpu) | 80.9 / 80.9 | 223.7 | 11.3 | 0.262 |
| pointnet2 | 5 | 0 | pyg (torch cpu (8 threads)) | 82.5 / 82.9 | 146.0 | 15.0 | 0.312 |

Notes:

- The runs of the table shared the machine (Apple M5 Pro, 64 GB) with other
  GPU and CPU jobs, so their times are noisy (the epochs of a run vary by up
  to 1.8x). On an idle GPU, one mlx-graphs PointNet++ training step takes
  0.42 s (about 53 s per epoch).
- ``fps`` alone (32 clouds of 1024 points, ratio 0.5): 1.9 ms with the Metal
  kernel, 132 ms with torch_cluster on the CPU; the sampled points are the
  same (``random_start=False``).
- PyG's ``radius`` keeps the first ``max_num_neighbors`` points found,
  mlx-graphs' the closest ones: the neighborhoods can differ in dense regions.
